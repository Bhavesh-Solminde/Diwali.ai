# Windows v0.5 operating guide

Current-PC update: both builds' input handlers and button callbacks were rechecked read-only; see [controls review](CONTROLS-CURRENT-PC.md). Direct capture now works for both versions. [Live results](LIVE-CONTROL-RESULTS-CURRENT-PC.md) verify v0.5 B/S, pause, accumulation, reduction, scene nominal lot 100, lagging statistics and net supply reconciliation. Older capture-failure and no-live-trade text below is historical; exact fill/cash accounting remains unverified.

Evidence: hashed installed assembly, read-only decompilation and isolated execution diagnostics. Running executable detected; live chart rendering remains unverified. Both native capture interfaces time out. Esc was sent once to request documented windowed mode; capture still timed out. No live player trades have been submitted during this research.

Executable: `Krafer Agent Trader Sim/Kat-05(Win)/Market Simulation/MarketSimulation.exe`.

B/Buy consumes asks through a marketable order and calls Long; S/Sell consumes bids then calls Short. Repeated same-side actions add one nominal lot each. An opposite action reduces the other side by one lot; after reaching flat, another action opens the opposite side. Lot initializer PlayerTradeSize=10; actual scene value unknown. There is no verified size-input UI. Position counts advance by one even if only part of the lot filled, so clicks, intended units and achieved quantity must be recorded separately.

Space pauses; hold fast-forward activates and sets speed 100, release sets 1. Drag pans, wheel zooms horizontally, Shift+wheel vertically. Esc requests windowed mode and F11 toggles fullscreen-window. These mappings are in installed code; chart/control outcomes are not runtime verified.

Keys 1/2/3 map to backup/restore/repeated futures, but backup contains a long[] to int[] cast that throws in isolated execution and is confirmed in IL. Even correcting that alone would leave portfolios, FIFO queues, price sets, player accounting and RNG unrestored. Do not use these branches for matched-state causal inference. Holding I adds 100 raw cash units to every ordinary agent each rendered frame, independently of market ticks and pause status; keep it untouched during research. It is capital injection, not organic recovery.

Five agent-update sweeps form one base candle. v0.5 adds chart aggregation: a displayed candle may group multiple base candles according to serialized candleAggregationSize. Scene setting unverified. maxCandles limits grouped retained history, not total simulation lifetime; initializer 1,024, aggregation initializer 1. Advertised ~16,000 needs scene/runtime confirmation. No verified one-minute mapping.

Green current book bars are bids, red asks, with width relative to the current maximum level. Installed code still contains historical depth capture/drawing behind drawOrderBars, despite the creator's removal statement; whether its scene/UI actually enables or usefully renders it is unknown. Do not call it categorically absent. Historical opacity saturates at 40 quantity units.

Ordinary agents initialize with integer cash 100,000–999,999 raw units and 10–99 coins, using independent unseeded System.Random objects. USD display divides raw cash/price/PnL by 100. Actual trader count and initialized scene price remain unknown. `usePortfolios` exists but is not consulted in the inspected execution code. Requests are sized to available inventory, but resting orders never call reservation methods and fills do not recheck collateral. Several orders can overcommit an agent and make balances negative. Initial finite balances are not enforceable finite exposure.

Maker probability is per request, not fixed trader type. Maker placement spans ±5% with triangular offsets; maker quantity 1–3 subject to currently available balances. Nonmaker placement spans ±0.005%, and quantity 2–4 follows the same three sinusoidal candle-index periods described in the v0.4 guide. The configured maker probability is unknown until scene/runtime settings are read.

Do not use display volume or PnL directly as labels. Ordinary fills add executed quantity, player fills add 100 times executed quantity. Multi-level taker orders update candle OHLC only once at their terminal fill price, omitting intermediate prices if they establish an extreme. Live chart update receives BestAsk rather than last execution price, including an empty-book sentinel possibility. Fees are declared but not applied by player Long/Short. Total PnL is realized-only and accumulates per-lot average-price differences without multiplying by lot size; floating PnL also omits lot size. Average entry is an integer weighted-by-click average, not reliably weighted by achieved quantity. Zero-fill market orders divide by zero.

Market-stat formulas: Q=(numBuys-numSells)*PlayerTradeSize; S=sum ordinary BTC; diluted/burned supply=S-Q; max-short supply=S+100*PlayerTradeSize. Market caps multiply the respective supply by last raw traded price and divide by 100 for UI dollars. The 100 assumption is a display convention in these methods, not an enforced position limit. Position worth uses average entry, not mark price. Stats refresh once per completed base candle, so they may lag clicks. The player has no cash/inventory portfolio object: t=null executions inject or remove assets on the ordinary-agent side. No closed-economy inference is justified for intervention runs.

LiqCycle plays audio. No margin, leverage, liquidation cascade, funding, iceberg/reserve, news, or strategic competing-whale mechanism was found in inspected application methods. Bankruptcy only assigns USD=0 and no caller was found. These findings apply to the inspected assembly, not a claim about every future build.

Native numeric export, persistent state files, external API, seed UI and supported batch/headless protocol: not found in inspected application scripts. Public getters are not an export interface. GetNetworkInput mixes a 25-candle-old price anchor with current book state, bins ordinary levels incorrectly and leaves a trailing zero. GetFuturePrices includes the anchor as its first label and reaches only +24 for a requested 25-element vector. The built-in bot experiments are not a validated model implementation to reuse. Scene activation of bot components is unknown; this work did not launch training.

# Missing explicit book midpoint: separate input audit

The existing87book features encode distances relative to the midpoint of each snapshot, quantities, spread and imbalance, and microprice minus midpoint. They do not explicitly retain the midpoint's absolute location or its motion across the60-second window. Trade VWAP features do retain their location relative to the latest completed candle close, so this is not a claim that all market-price information was missing.

A deterministic test demonstrates non-identifiability: proportionally scaling every bid/ask price while keeping quantities fixed leaves all87old shape features unchanged, while midpoint relative to a fixed candle anchor changes. This establishes a representation limitation, not that it caused the poor direction scores or that adding it will solve prediction.

`midpoint_scan.cpp` reuses the existing exact-decimal archive replay unchanged. It writes a separate midpoint sidecar with the same receipt grid, latest receipt/event clocks, sequence, age and validity fields. It preserves the snapshot-bridge, freshness, continuity, top20bounds and hard-clock exclusions. A snapshot alone is not promoted to a usable book before an accepted bridging update. No old feature/model/checkpoint is overwritten.

Before the full run: a two-hour real-archive preflight completed7,200seconds with7,198valid seconds and exact equality of all parent metadata/validity fields. Native synthetic tests compare with the original feature scanner and verify that price changes arriving later never enter an earlier grid and stale books remain invalid. Pure transformation tests verify zero first within-window change and rejection of invalid inputs. Do not relax an old exclusion to increase rows.
